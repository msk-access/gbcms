    Read Judgment¶

    How gbcms decides what one read says about one variant: REF, ALT, partial evidence of another allele, or depth only. This page is the spec: a table of read shapes and the call each gets, with the decision behind every call. The algorithms that implement it are in Allele Classification.

    The table is executable. tests/read_judgment_cases.py builds every shape (synthetic, four reads each) and tests/test_read_judgment_spec.py checks the engine's call for each one. A decided case fails when the engine breaks its rule. An open case pins today's call until its decision lands, so a change to it shows in review instead of slipping in with an unrelated fix.

    How a change to read judgment is made¶

    1. Spec first. A change to how reads are judged starts here: the shapes it affects, their call today, the proposed call, and the evidence (the read census's verdict on each shape, real-data counts adjudicated per read, and what other tools do: GATK, samtools/bcftools, fgbio, VarDict, Strelka2, freebayes, bam-readcount, LoFreq and the original GetBaseCounts, plus the domain's own tools (for RNA: GATK's RNA practice, STAR, ASE counters, RNA variant and editing callers) and the published literature, saying where a tool's handling is not documented). The census changes in step with a rule about read inputs (what a read contributes), so for such a rule it cannot be the evidence: check the bases in question themselves and the mates' alignments, ITD and indel rows first. Other tools' practice is a floor, not a ceiling: where none sets a standard, or the measurements support a better rule, propose that rule and say where and why it departs from practice.

    Fix the class, not the row. Start from the mechanism: what about the read, the alleles or the judge makes the call wrong, stated without the row that showed it, and the rule that follows from the principles below. The row is one instance, so the cases cover the other shapes of the same mechanism (SNV, MNV, indel and delins; repeat and unique sequence; read ends, strands and qualities). A cutoff comes from a mechanism (an error rate per telling base, a quality, a read length), never from where a measurement splits or from an oracle's own cut, and is checked across the values users set. A rule narrower than its mechanism says why, or is recorded as a known partial with the general rule ticketed. Judge it on data the bug was not found in, against a truth that does not share the rule. Before proposing, look for earlier work on the same mechanism: this register, REJECTED.md, and closed issues, whose comments hold the measurements behind past decisions. 2. Decide. The operator decides; the decision gets an entry in the register below, stating the mechanism it follows from and naming any earlier decision it amends. 3. Then code. The implementation turns the case table's open cells into decided ones. A test expectation that changes is part of the decision, never a side effect of the fix.

    Principles¶

    • Count the given allele; judge bases, not placement. A read is ALT only when its own bases carry the ALT, and REF only when its bases show REF where the alleles differ. Alignments can be wrong, so the CIGAR's placement of an indel never decides a call on its own (AGENTS.md invariant 7).
    • Informative reads only. A read that cannot tell the alleles apart (one that starts or ends inside an indel's repeat tract, or holds no window of a complex variant) counts toward depth only.
    • One oracle. For pure indels, the read census (tests/census.py) judges each read by its bases alone; the engine's pure-indel counts are checked against it.
    • The sequence judge resolves sequence, not haplotypes (--read-judge sequence, #304; operator 2026-10-25). It asks which local sequence a read's own bases spell at the row: REF, the row's ALT, or another allele at its site (the row's candidate sequences). Contexts (other listed rows, the guard's recurring background, alleles the reads spell away from the site) only explain the read's other differences, so they never pass for the row's allele. No linkage, no phasing: a variant linked to the row elsewhere never credits a read.

The rules path is unchanged. The base rule and its amendments, oldest first: Every complex event is read by one pair of equal-length junction windows at one flank, the same for both alleles: the shorter allele's whole window (its event, grown through repeats, with two flank bases each side) against as many of the longer allele's bases, read inward from that flank, then on through the rest of the longer allele as far as the read reaches (RJ-9). Windows of equal length at one anchor give a REF and an ALT molecule the same number of read starts that can judge them, so the VAF is unbiased without padding the shorter window (which cost a third of the reads); reading junctions from either flank instead would let the longer allele count at both ends. Past 50 bases nothing changes in practice: only reads over the variant's first base (or admitted by a clip) are counted, so the far junction never decided a call. The flank is the POS flank; an RNA variant whose POS flank is cut by an exon edge reads from the other one (amended 2026-10-16, RJ-27: an exon start in the flank or at the event's first base cuts the left flank, an exon end only inside it, so an exon end where the event starts leaves the left flank whole), and when both alleles pass 50 bases the windows run from the flank nearer the first difference (an event ending a long run is out of reach from the other); a read judged from the right counts though it starts past POS, as the other allele's molecule starting there would.
